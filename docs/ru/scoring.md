# Скоринг 0–100: как считается балл готовности

## Зачем балл

Скоринг решает одну задачу: **в каком порядке откликаться**, когда постов больше, чем времени. Балл — это не «оценка поста», это приоритет вашего времени.

## Формула

```
Балл = Точность ниши + Интент + Бюджет + Свежесть − Штраф за старость
```

| Компонент | Условие | Баллы |
|---|---|---|
| **Точность ниши** | Точное попадание (чат-бот, ИИ-агент, RAG, n8n, aiogram, «внедрить ИИ»…) | +40 |
| | Смежная тема (парсинг, CRM, автоматизация, Telegram, Python…) | +15 |
| | Не попал — на этом пост выпадает из отчёта | 0 |
| **Интент** | Названы деньги (бюджет, оплата, ₽…) | +25 |
| | Срочность (срочно, сегодня, завтра…) | +15 |
| | Готов к контакту (ТЗ есть, «детали в ЛС») | +10 |
| **Бюджет** | Сумма в коридоре 1К–600К ₽ | +10 |
| **Свежесть** | <24 часов | +10 |
| | <72 часов | +5 |
| | Старше ~17 дней | −15 |
| **Красные флаги** | Наём персонала («вакансия», «ищем SMM-менеджера»...) | пост → 0, «не заказ» |
| | Rescue («доделать», «предыдущий исполнитель пропал») | −10 + ⚠ флаг в отчёте |
| | ToS-риск («спарсить базу клиентов») | −15 + ⚠ флаг в отчёте |
| | Lowball (бюджет < 5К ₽ в коридоре) | ⚠ флаг «не тратить время» |

## Пороги

- **🔥 60+** — «связаться сегодня». Точная ниша + деньги/срочность/ТЗ. Таких в прогоне обычно 0–3.
- **🌤 40–59** — «мягкий заход». Или точная ниша без денег, или смежная с деньгами. Смотреть глазами.
- **<40** — не тратить время.

## Технические детали (для агентов)

- **Word-boundary матчинг.** Ключевое слово ищется границей слова: «бот» не матчится внутри «работа», «ии» не матчится внутри «позиции». Это главное отличие наивного парсера от рабочего.
- **Нормализация.** Текст приводится к нижнему регистру, «ё»→«е», пробелы сжимаются.
- **Бюджет из текста.** Regex ловит `NNN ₽/руб/тыс` и берёт числа 1К–600К — мусорные суммы («по 100 руб. за отзыв») отфильтровываются.
- **Объяснение каждого балла.** В отчёте рядом с постом — строка «почему»: `точное: rag; деньги: бюджет; срочно: срочно`. Балл без объяснения — не балл.

## Почему 0–100, а не «горячий/холодный»

Градуированная шкала позволяет: (а) ранжировать список, (б) двигать пороги под нишу в конфиге без правки кода, (в) считать экономику — цена тёплого лида имеет смысл только когда «тёплый» определён числом.

## Калибровка под нишу

Пороги и ключи — в `parser-config.yaml`. Если в вашей нише все посты «горячие» или все «холодные» (поток сместился), двигайте пороги `hot_threshold`/`warm_threshold`, не переписывайте логику — правило из практики: логика стабильна, словарь живой.
